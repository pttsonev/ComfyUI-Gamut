# F_0.1.0 — Gamut core: colour engine, tagged EXR IO, LTX HDR, optional OCIO

**Status:** planned · **Target version:** v0.1.0 · **Branch:** `feature/gamut-core`
**Peer review:** APPROVED (gpt-6-astra, xhigh, 3 rounds)

## Overview

`ComfyUI-Gamut` is a VFX colour-management node pack for ComfyUI. It exists because
every EXR writer in the ComfyUI ecosystem uses OpenCV, which cannot write EXR header
attributes — so every EXR produced is an untagged pile of numbers that Nuke/OCIO has
to be told about by hand. This pack writes `chromaticities` and `colorSpace`, applies
verified primaries rotations, and keeps float data in float.

Primary near-term client: the LTX-2 HDR IC-LoRA path, whose decoded output is
**linear light on Rec.709 primaries** and currently reaches disk unrotated and untagged.

## Verified facts this plan rests on

Each was established by measurement in the design session, not assumed.

1. **LTX HDR decodes to Rec.709 primaries.** Upstream `ltx_core/hdr.py` declares
   `HDRTransfer.LOGC3.native_primaries -> Primaries.REC709`, and the pipeline returns
   linear via `to_hdr_linear(..., out_primaries=Primaries.REC709)`.
2. **The installed checkpoint is LogC3.** `ltx-2.3-22b-ic-lora-hdr-0.9.safetensors`
   carries `__metadata__.hdr_transform = "logc3"` — the exact field
   `hdr_ic_lora.py:207` reads. ACEScct exists upstream but is unreachable with these
   weights, and the ComfyUI node has no transfer selection regardless.
3. **`Rec.709 -> ACEScg` confirmed four independent ways** — colorimetric derivation
   from published primaries with Bradford CAT; Lightricks' own `_SRGB_TO_ACESCG`
   (agrees to 5e-06); the ACES published matrix; and OCIO 2.5.2 (agrees to 4.5e-07).
4. **`OpenEXR` 3.4.4 writes the tags cv2 cannot.** Verified by writing a half-float
   ZIP EXR with `chromaticities` + `colorSpace` and reading both back intact.
5. **OCIO is not a slow path.** On 8 × 1920×1080 float32, OCIO's CPU processor ran
   43 ms vs 122 ms for an equivalent torch matmul on CPU (and 88 ms on GPU including
   the host→device copy). It agrees with torch to 1.07e-06.
6. **OCIO's ARRI LogC3 (EI800) matches LTX's implementation** to 5.1e-05 relative —
   the same curve. We still implement it natively so the core has no optional dep.

## Architecture

### Colour state travels beside the image, never inside it

ComfyUI's `IMAGE` stays exactly `torch.Tensor [B,H,W,C] float32` so every existing
node still connects. A `COLORSPACE` type carries the declaration:

```python
@dataclass(frozen=True)
class ColorSpace:
    primaries: str   # "rec709" | "acescg" | "ap0" | "rec2020"
    transfer: str    # "linear" | "srgb" | "logc3" | "acescct" | "g22" | "g24"
    source: str      # "exr:chromaticities" | "widget" | "node:<name>" | "ocio:<space>"
```

`source` records *how we know*, which is what lets `Color Space Info` distinguish
"ACEScg because the file said so" from "ACEScg because someone typed it".

Every node accepts an optional `colorspace` input and always emits one. When the input
is absent the node's own widgets are authoritative. `Load EXR` emits a ColorSpace read
from the real header; `Save EXR` consumes one and writes the tags back.

### Two layers with a hard boundary

- **Core** — `torch`, `numpy`, `OpenEXR` only. Completes the LTX HDR path unaided.
- **OCIO bridge** — imported lazily behind a capability check. If `opencolorio` is
  absent the OCIO nodes do not register and the log states why once. **Core modules
  must never import the bridge.**

## Modules

`ColorSpace` dataclass (above), `PRIMARIES` and `TRANSFERS` registries, plus
`describe(cs) -> str` for the info node. No torch dependency beyond typing.

All 12 ordered pairs across the four primaries are present as explicit matrices — no
composition at runtime, and `test_primaries.py` asserts every selectable pair resolves.

`convert(img, src, dst) -> Tensor` applies the matrix on the **last** axis
(`img @ M.T`), identity when `src == dst`, `KeyError` naming both spaces when the pair
is unknown. Works on `[...,C]` of any rank; requires C >= 3 and passes any 4th channel
(alpha) through untouched.

**Linear-light precondition.** A primaries matrix is only valid on linear light.
`convert` therefore takes the incoming `ColorSpace` and **raises `ValueError` when
`transfer != "linear"`**, naming the offending transfer and instructing the caller to
run `Gamut: Transfer` (decode) first. Multiplying log or gamma-encoded codes through a
matrix is exactly the silent wrongness this package exists to prevent, so it fails
loudly rather than proceeding. An untagged input (no `ColorSpace` wired) is **assumed
linear**, and the node's tooltip and the README both say so explicitly.

### `gamut/transfer.py`
Pure functions, all operating on linear-vs-encoded, no primaries knowledge:

- `srgb_encode/decode` — piecewise, thresholds 0.0031308 / 0.04044823627710817
- `logc3_encode/decode` — ARRI EI800 constants A=5.555556 B=0.052272 C=0.247190
  D=0.385537 E=5.367655 F=0.092809 CUT=0.010591. **Must match Lightricks bit for bit.**

  **Domain:** `logc3_decode` takes ordinary encoded LogC3 codes and returns linear. It
  is **unclamped in both directions** — the curve is defined outside `[0,1]`, and
  clamping there would silently destroy data: linear `100` encodes to approximately
  `1.064016` (from the EI800 constants above), which a `[0,1]`-clamped inverse would
  crush to `55.079577`. Since the whole point of this package is HDR highlights
  surviving to disk, the generic curve
  never clips. Domain clamping belongs to the caller that actually has a bounded
  domain — see `gamut/ltx.py`, where the VAE's `[0,1]` range makes it correct.
  `logc3_decode` does **not** take the VAE's `[-1,1]` range. Upstream's `LogC3.decompress` accepts `[-1,1]` and rescales
  internally with `(z+1)/2`, while the ComfyUI wrapper pre-multiplies by `*2-1` — the
  two cancel exactly, so the curve is applied to the `[0,1]` value either way. Keeping
  the VAE rescale out of the generic function is what prevents the trap: calling
  `logc3_decode(x*2-1)` on `x=0.5` yields **-0.017290** instead of the correct
  **0.513383**. Regression fixture pins `logc3_decode(0.5) == 0.513383`, and
  `gamut/ltx.py` documents that it deliberately performs no rescale.
- `acescct_encode/decode` — AMPAS S-2016-001; A=10.5402377416545 B=0.0729055341958355
  X_BRK=0.0078125 Y_BRK=0.155251141552511 LOG_M=17.52 LOG_B=9.72
- `gamma_encode/decode(x, g)` — **sign-preserving** power,
  `sign(x) * abs(x)**g`. A plain `pow` returns NaN on negative input, and negatives
  arise routinely from an out-of-gamut primaries rotation (e.g. saturated blue
  Rec.709 -> ACEScg), so the naive form would poison whole frames. The piecewise
  sRGB, LogC3 and ACEScct curves are already negative-safe by construction (their
  sub-threshold branches are linear, and ACEScct guards its `log2`), but each is
  covered by a negative-input test regardless.

`encode(img, curve)` / `decode(img, curve)` dispatch on the registry. Negatives are
preserved by default (`clamp_negatives: bool = False`) — clipping is the caller's
decision, never a silent default.

### `gamut/exr.py`
`read_exr(path) -> (np.ndarray, ColorSpace | None, dict)` — returns pixels, the
ColorSpace inferred from `chromaticities`/`colorSpace` when present (matching
chromaticities to a known set within 1e-4, else `None`), and the raw header.

**Untagged files are the common case** (every cv2-written EXR in the wild). `read_exr`
returns `None` for the ColorSpace; `GamutLoadEXR` then falls back to its
`fallback_primaries` / `fallback_transfer` widgets and emits a ColorSpace with
`source="widget:fallback"`. The node never invents a tag silently — the provenance
field records that a human chose it, and `Gamut: Color Space Info` reports the
difference. Chromaticities present but matching no known set are reported verbatim in
the info string rather than being forced to the nearest match.

`write_exr(path, arr, colorspace, half=True, compression="zip")` — sets
`chromaticities` (float[8]) and `colorSpace` (the transfer's display name), writes
RGB or RGBA. Raises on failure; never silently swallows.

### `gamut/highbit.py`
`save_png16` / `save_tiff16`, plus `tpdf_dither(x, bits)` — triangular PDF dither
applied **before** quantisation. Dither is opt-in and off by default.

### `gamut/ltx.py`
`decode_ltx_hdr(image, target_primaries="rec709", exposure=0.0, clamp_negatives=True)`.

Mirrors the ComfyUI LTXVideo node's contract. Input is VAE output in `[0,1]`. This
adapter — and **only** this adapter — clamps its input to `[0,1]` before decoding, to
match upstream's behaviour exactly for the VAE domain, where codes outside that range
are not meaningful. It performs **no `*2-1` rescale**: upstream's wrapper multiplies by
`*2-1` and `LogC3.decompress` immediately undoes it with `(z+1)/2`, so the pair cancels
and applying only one half is the -0.0173 trap documented above. It calls
`logc3_decode(image)` directly.

**No upper clamp on the output** — linear values above 1.0 are real highlight data and
must reach the EXR. Rotates Rec.709 -> target when asked. Returns `(tensor, ColorSpace)`.

### `gamut/ocio_bridge.py`
`available() -> bool` (cached), `get_config(spec)` where spec is a built-in name,
`$OCIO`, or a path; `list_spaces(cfg)`, `apply_transform(arr, cfg, src, dst)`,
`apply_display(arr, cfg, src, display, view)`, `apply_file_transform(arr, path, direction)`.

`apply_display` **requires an explicit source colour space** — OCIO's
`DisplayViewTransform` has no meaning without one, and defaulting to the config's
`scene_linear` role would silently misread LTX's Rec.709 output as ACEScg. The node
resolves `src` from a wired `COLORSPACE` when present and otherwise from its own
dropdown; it never guesses.
Default config: `cg-config-v4.0.0_aces-v2.0_ocio-v2.5`.

Uses `PackedImageDesc` on a contiguous float32 copy — the measured fast path.

## Nodes

All register under category `Gamut/<group>`. All node classes live in `nodes/`,
import only from `gamut/`, and contain no colour maths of their own.

| Node | Inputs | Outputs |
|---|---|---|
| `GamutColorSpaceConvert` | IMAGE, from/to primaries, COLORSPACE? | IMAGE, COLORSPACE |
| `GamutTransfer` | IMAGE, direction, curve, COLORSPACE? | IMAGE, COLORSPACE |
| `GamutLoadEXR` | path, tonemap-preview? | IMAGE, MASK, COLORSPACE |
| `GamutSaveEXR` | IMAGE, prefix, primaries, transfer, half, compression, start_frame, frame_pad, version, COLORSPACE? | — (OUTPUT_NODE) |
| `GamutSaveHighBit` | IMAGE, format(png16/tiff16), transfer, dither | — (OUTPUT_NODE) |
| `GamutLTXHDRDecode` | IMAGE, target_primaries, exposure | IMAGE, COLORSPACE |
| `GamutOCIOTransform` | IMAGE, config, src, dst | IMAGE, COLORSPACE |
| `GamutOCIODisplayView` | IMAGE, config, display, view | IMAGE |
| `GamutApplyLUT` | IMAGE, lut_path, direction, interpolation | IMAGE |
| `GamutColorSpaceInfo` | IMAGE?, path?, COLORSPACE? | STRING |

`GamutSaveEXR` follows spacepxl's IO discipline: `folder_paths.get_save_image_path()`
for relative prefixes, absolute paths honoured, `_v001` version and zero-padded frame
numbers from `start_frame` (default 1001), and **refuses to overwrite an existing
file** rather than silently clobbering a prior render.

## Testing

The reviewed `ComfyCompositing-ltx-aces` shipped a fabricated matrix because nothing
checked it. Tests are therefore the point of this package, not an afterthought.

- `test_primaries.py` — every matrix asserted against an in-test colorimetric
  derivation (primaries + Bradford, computed from first principles in the test itself)
  to 1e-6, and against OCIO to 1e-5 when installed. Round-trip A->B->A to 1e-6.
  Row sums of any same-white-point matrix == 1.0.
- **Regression guard** — an explicit test that `rec709->acescg` is NOT the fabricated
  `[[0.6724,0.1536,0.1740],...]` matrix, named so the value can never reappear.
- `test_transfer.py` — LogC3 asserted against the exact Lightricks constants on a
  21-step ramp to 1e-6; round-trip for every curve to 1e-6; sRGB against known pairs.
- `test_exr.py` — write/read round-trip preserving `chromaticities` within 1e-6 and
  `colorSpace` exactly; half and float; RGB and RGBA.
- `test_ltx.py` — decode of a known VAE-range ramp against values computed from the
  upstream formula; asserts **no upper clamp** (a 1.0 input survives as >1.0 linear).
- `test_nodes.py` — every node's `INPUT_TYPES`/`RETURN_TYPES`/`FUNCTION`/`CATEGORY`
  present and consistent; mappings complete; import works with OCIO absent.

**The suite must pass with `opencolorio` not installed** — OCIO comparisons skip via
`pytest.mark.skipif`. ComfyUI itself is not importable in CI, so node modules must
guard `import folder_paths` and tests exercise the pure functions.

## Out of scope for v0.1.0

Video/mp4 encode · DPX/Cineon IO · latent EXR (spacepxl covers it) · LUT generation ·
ML bit-depth expansion (rejected on evidence — it estimates data that was never
measured) · custom tonemap operators beyond what OCIO provides · the LTX motion
instability, which is parked as a separate diagnosis and is very likely temporal
rather than colorimetric.
